# rem0002 audit logs

**branch:** rem0002-audit-logs · **status:** planning
**depends on:** rem0001 (access helpers), rem0003 (common hooks location)

## goal

record create / update / delete / login / logout across collections and globals in an `audit-logs` collection, based on `references/auditlogs.ts`.

## to build

- `audit-logs` collection. see the reference: read-only from the admin, `create`/`update` are always false.
- common hooks in `src/common/hooks/`: `auditLogAfterChange(slug)`, `auditLogAfterDelete(slug)`, `auditLogAfterLogin`, `auditLogAfterLogout`. these were not in the references and must be written.
- write logs with `overrideAccess: true`, and never fail the parent operation if logging fails. catch the error and log it.

## security / concerns

- [ ] redact sensitive fields from `data`: `password`, `hash`, `salt`, `apiKey`, `enableAPIKey`, `resetPasswordToken`, `_verificationToken`.
- [ ] restrict delete to super users only, so logs can't be quietly erased.
- [ ] never audit `audit-logs` itself (avoids loops).
- [ ] get the ip from `x-forwarded-for` behind a proxy. it can be spoofed, so record it as is and don't trust it.
- [ ] retention: decide max age or size and how to prune (payload jobs).
- [ ] add a tenant field once rem0000 lands.
