# rem0001 access control

**branch:** rem0001-access-control · **status:** planning
**depends on:** rem0000 design (user ↔ tenant ↔ access shape)

## goal

replace the current `roles` collection + `users.role` with the `users-access` model from `references/`: one access record with per-slug rows (`hidden`, `read`, `create`, `update`, `admin`, `delete`, `super_user`), assigned to users.

## current state

- `src/utilities/access.ts`: `accessCheck` / `accessCheckResolver` read permissions from `user.role` (roles collection).
- `src/access/checkPermission.ts`: an older, unused implementation. delete it.
- migrations `20260509_*` added `super_user` and roles data. the switch needs a data migration from roles to users-access.

## references (from another project, clean before use)

- `references/access.ts`, `references/user.access.ts`, `references/user.ts`
- remove project-specific fields: `h2a_oasys_emp_id`, `doj`, `old_id`, `operator`, `department`, `restaurant`, microsoft sso / `auth_method`.
- imports from `@/common/...` must match the folder structure in `CLAUDE.md`.

## known issues to fix while porting

- [ ] `accessCheck` returns `where` even when permission is false. only return `where` when `defaultAccessReturn` is true, as the current code does.
- [ ] `users-access` read refine crashes on `userAccess.id` when the user has no access record.
- [ ] `logger.info` on every check and `console.log` in `accessHiddenBySlug`: switch to `debug` or remove.
- [ ] the `access` ("api access") checkbox is never checked. implement it or drop it.
- [ ] default rows come from config slugs only at create time. existing records won't get rows for collections added later. add a sync, or treat a missing row as "hidden + no access" explicitly.
- [ ] the `create-first-user` bypass is pathname-based. keep it narrow, or rely on the `ensureFirstUserIsSuperUser` hook.
- [ ] logging `where: ${where}` prints `[object Object]`.
